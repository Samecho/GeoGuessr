# Built-in Africa library

Reviewed 2026-09-26. The read-only Africa preset is `public/libraries/africa.json` and its manifest is `src/data/africa-library-manifest.json`. It was promoted from the reviewed personal-library export `street-clues-custom-library-africa-road-prefixes.json` after importer validation and browser checks. It contains 93 bilingual clues: 55 with embedded images and 38 text-only. Images stay embedded in the static JSON and are loaded only when the user selects this library. The Global library and its separate scoring data are not modified.

The preset covers exactly 14 documented candidates: Botswana, Eswatini, Ghana, Kenya, Lesotho, Namibia, Nigeria, Réunion, Rwanda, São Tomé and Príncipe, Senegal, South Africa, Tunisia, and Uganda. This is the scope of the supplied JSON, not a claim that every African country is fully researched. A country's absence from this preset is not evidence against it in the Global library. Manual scope intersects this list without adding countries or scores.

The source material for the pre-existing African clue cards came from the owner's local `tuxundoc/非洲/*/index.html` tutorial archive and associated images. The author permission reported by the owner applies to this project; the code's MIT license does not cover the tutorial images. The image audit is [here](AFRICA_PLATE_IMAGES.md). Twelve text-only road-number prefixes were added from local chapters and cited road authority/government documents; the source and per-prefix multiplier review is [here](AFRICA_ROAD_PREFIXES.md). The personal JSON did not carry a per-clue source field; this preset therefore retains the available chapter-level provenance and does not claim that every multiplier is a measured frequency or independently fact-checked statistic.

The Africa preset uses the same versioned `CustomLibrary` JSON parser and likelihood-multiplier engine as personal libraries, but it is bundled and read-only. This is a deliberate data-engine distinction from the original Global library's source-fact evidence model. The two libraries never score one another's clues. The app loads this JSON on demand from its own static site; there is no external API call. `npm run data:validate` checks its schema, image count, candidate list and weight targets on every build.
